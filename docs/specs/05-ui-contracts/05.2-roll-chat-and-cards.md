## 1) Intent

Define the **UI contracts** (data in/out) for action/talent cards, roll dialogs, and chat messages. Focus on **JSON payloads** and rules for Fortune rerolls and degree‑of‑success rendering. Styling and theme are out of scope.

---

## 2) Contracts

### 2.1 Roll request → engine (01.1)

```ts
/** @spec 05.2 */
export interface RollRequest {
  actorId: string;
  talentId?: string;                 // optional for ad‑hoc tests
  seed?: string;                     // optional RNG seed for determinism
  test: import('../01-core-rule-engine/01.1').TestInput; // includes ct & modifiers
}
```

### 2.2 Engine result → chat message

```ts
/** @spec 05.2 */
export interface RollMessage {
  actorId: string;
  talentId?: string;
  request: RollRequest;                  // echo for audit
  result: import('../01-core-rule-engine/01.1').TestResult; // includes degree, margin, halfCrit, trueCritical
  timestamp: string;                     // ISO time
  version: string;                       // schema version
}
```

### 2.3 Fortune reroll flow

```ts
/** @spec 05.2 */
export interface RerollRequest {
  messageId: string;                // existing chat message
  index: 0|1;                       // which die to reroll
  by: 'self'|'forced';              // who triggers it
}

/** @spec 05.2 */
export interface RerollAppend {
  messageId: string;
  reroll: import('../01-core-rule-engine/01.1').RerollEntry; // appended to result.rerolls
  result: import('../01-core-rule-engine/01.1').TestResult;  // recomputed totals
}
```

## 3) Rendering rules (mechanics‑facing)

* **Degree banners:** Four states from 01.1 (`crit-fail`, `fail`, `success`, `crit-success`).
* **Half‑Crit badge:** Show `halfCrit:'success'|'fail'|'cancelled'` when set; otherwise hide.
* **True Critical badge:** Show when `trueCritical===true`.
* **Symbols:** Render talent `cost` arrays with glyphs ◯ ⊖ ⊚ ⊘ ⊜; include accessible text (e.g., `aria-label="cost: 2 AP"`).
* **Breakdown:** Display dice results, modifiers by source, total, and margin vs CT.

---

## 4) Validation & invariants

**R-05.2-01** Chat messages **MUST** embed the exact `TestResult` JSON from 01.1; mutation of prior results is not allowed—rerolls append history.

**R-05.2-02** Fortune prompts **MUST** respect 01.1’s once‑per‑die rule and actor resource checks (03.1); violations throw `ENGINE_RULE_VIOLATION`.

**R-05.2-03** A11y: interactive elements for rerolls/buttons **MUST** be keyboard accessible and labelled; no information conveyed by color alone.

**R-05.2-04** i18n: No hard‑coded user text in the payload; UI renders localized strings based on enums/keys.

---

## 5) Acceptance Criteria (AC)

**AC-05.2-01** A roll produces a chat message with a payload that round‑trips to the `RollMessage` interface and contains `result.degree`, `result.margin`, `result.halfCrit`, and `result.trueCritical`.

**AC-05.2-02** A Fortune reroll updates the message by appending a `RerollAppend` entry; previous results remain visible.

**AC-05.2-03** Cost symbols render with accessible labels and the correct numeric AP inferred from 02.2 parsing.

**AC-05.2-04** A11y checks pass: all interactive controls are reachable via keyboard and labelled.
