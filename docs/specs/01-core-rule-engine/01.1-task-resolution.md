## 1) Intent

Define the *authoritative* rules and pure-function API for resolving a task/check and classifying the **Degree of Success (DoS)** from a **2d10** test versus a **Challenge Threshold (CT)**. This spec is deterministic and testable without Foundry runtime.

Out of scope: setting prose; UI copy; damage/condition application (other specs consume the results).

---

## 2) Terminology

* **Test:** Roll **2d10**, add modifiers, compare the **Total** to **CT** to determine DoS.
* **CT:** Numeric target the roll must meet/beat (derived per 01.3).
* **DoS (four states):** *Critical Failure*, *Failure*, *Success*, *Critical Success*.
* **Half‑Crit:** If either test die is **1** → half‑crit *fail*; if either is **10** → half‑crit *success*; if one die shows **1** and the other **10**, they **cancel** (no half‑crit effect).
* **True Critical:** When DoS is already **critical** and the dice are **\[1,1]** (crit‑fail) or **\[10,10]** (crit‑success). Downstream effects of the critical are **doubled**; 01.1 flags this, consumers enact doubling.
* **Fortune Reroll:** Spend Fortune to **reroll dice** in a test—**one die per Fortune**—and **no die may be rerolled more than once** in that test. Characters may **force NPCs/hazards** to reroll with their Fortune; NPCs/hazards cannot force PCs.

---

## 3) Rules (normative)

R-01. All task/tests use **2d10** test dice; add modifiers to produce **Total**.

R-02. Compare **Total** to **CT** using inclusive critical bands (§5) to determine DoS.

R-03. **Half‑Crits** are detected from die faces and **do not** alter DoS; they emit tags consumed by actions/items.

R-04. **True Critical** is flagged only when DoS is critical and dice are \[1,1] (crit‑fail) or \[10,10] (crit‑success).

R-05. Fortune: spending **N** Fortune rerolls **N** distinct dice in the test; **each die can be rerolled at most once**. Forced rerolls may only target NPCs/hazards.

R-06. The resolution algorithm **MUST** be pure and deterministic with injected RNG.

## 4) API (pure functions)

> All exports include `@spec 01.1` and accept an optional RNG for deterministic tests.

```ts
/** @spec 01.1 */
export type DegreeOfSuccess = 'crit-fail' | 'fail' | 'success' | 'crit-success';

/** @spec 01.1 */
export interface Modifier { id: string; value: number; type: string; source: string; }

/** @spec 01.1 */
export interface RollBreakdown { dice: [number, number]; sum: number; modifiers: Record<string, number>; }

/** @spec 01.1 */
export interface RerollEntry { by: 'self'|'forced'; index: 0|1; from: number; to: number; }

/** @spec 01.1 */
export interface TestInput {
  ct: number;                    // Challenge Threshold
  modifiers: Modifier[];         // from 01.4 (already filtered/stacked)
  dice?: '2d10';                 // optional (defaults to '2d10'); MUST be '2d10' if provided
  options?: { allowFortune?: boolean };
}

/** @spec 01.1 */
export interface TestResult {
  total: number;                 // final total after modifiers
  baseRoll: RollBreakdown;       // raw dice + per-source modifiers
  degree: DegreeOfSuccess;       // four-state DoS
  margin: number;                // total - ct
  ct: number;                    // echo
  halfCrit: 'none'|'success'|'fail'|'cancelled';
  trueCritical: boolean;         // see §3 R-04
  rerolls?: RerollEntry[];       // audit trail
  tags: string[];                // e.g., ['fortune-reroll','half-crit-success']
  logs?: string[];               // machine-readable trace
}

/** @spec 01.1 */
export function rollTest(input: TestInput, rng?: RNG): TestResult;

/** @spec 01.1 */
export function classifyDegree(total: number, ct: number): DegreeOfSuccess; // pure

/** @spec 01.1 */
export function detectHalfCrit(dice: [number, number]): 'none'|'success'|'fail'|'cancelled';

/** @spec 01.1 */
export function isTrueCritical(degree: DegreeOfSuccess, dice: [number, number]): boolean;

/** @spec 01.1 */
export function applyReroll(prev: TestResult, req: { by: 'self'|'forced'; index: 0|1 }, rng?: RNG): TestResult; // once-per-die validated
```

## 5) Algorithm (normative pseudocode)

```text
function rollTest(input, rng):
  assert input.ct is finite number  // V-02
  assert input.dice is undefined or '2d10' // V-01
  dice = rng.roll2d10()              // [d0, d1], each 1..10
  sum  = dice[0] + dice[1]
  mod  = sum(applyModifiers(input.modifiers)) // 01.4 governs stacking/type
  total = sum + mod
  degree = classifyDegree(total, input.ct)
  half  = detectHalfCrit(dice)
  isTC  = isTrueCritical(degree, dice)
  return { total, baseRoll:{ dice, sum, modifiers: bySource }, degree, margin: total - input.ct, ct: input.ct, halfCrit: half, trueCritical: isTC, tags: [] }

function classifyDegree(total, ct):
  margin = total - ct
  if margin <= -10: return 'crit-fail'     // inclusive lower bound
  if margin < 0:   return 'fail'
  if margin >= 10: return 'crit-success'   // inclusive upper bound
  return 'success'

function detectHalfCrit([a,b]):
  const has1 = (a===1 || b===1)
  const has10 = (a===10 || b===10)
  if (has1 && has10) return 'cancelled'
  if (has1) return 'fail'
  if (has10) return 'success'
  return 'none'

function isTrueCritical(degree, [a,b]):
  return (degree==='crit-fail' && a===1 && b===1) || (degree==='crit-success' && a===10 && b===10)
```

## 7) Validation & errors

**V-01:** Tests **MUST** use `'2d10'`; other expressions **MUST** throw `AvantError(ErrorCode.DICE_EXPR)`.

**V-02:** A non‑finite CT **MUST** throw `AvantError(ErrorCode.CORE_CT_INVALID)`.

**V-03:** `applyReroll` **MUST** reject attempts to reroll the **same die more than once** within a test (`AvantError(ErrorCode.ENGINE_RULE_VIOLATION, { rule: 'once-per-die' })`).

---

## 8) Acceptance Criteria (AC)

**AC-01** Determinism: With a seeded RNG and identical `TestInput`, `rollTest` returns identical `TestResult`.

**AC-02** Boundaries:

* Given `ct=15`, totals map as: `<=5` → **crit-fail**; `6..14` → **fail**; `15..24` → **success**; `>=25` → **crit-success**.
* Exactly `total==ct` → **Success**; exactly `total==ct+10` → **Crit Success**; exactly `total==ct-10` → **Crit Fail**.

**AC-03** Half‑Crit detection:

* Dice `[1,7]` → `halfCrit:'fail'`.
* Dice `[10,9]` → `halfCrit:'success'`.
* Dice `[1,10]` or `[10,1]` → `halfCrit:'cancelled'`.

**AC-04** True Critical:

* Dice `[10,10]` with `total>=ct+10` → `degree:'crit-success'` and `trueCritical:true`.
* Dice `[1,1]` with `total<=ct-10` → `degree:'crit-fail'` and `trueCritical:true`.

**AC-05** Fortune rerolls:

* Applying `applyReroll({ index:0 })` changes `baseRoll.dice[0]` and appends a `rerolls` entry; recompute `total/degree`.
* A second attempt to reroll `index:0` in the same test throws `ENGINE_RULE_VIOLATION` (once‑per‑die).

**AC-06** Serialization: `TestResult` round‑trips to JSON without loss (excluding RNG instance).

**AC-07** i18n: No user‑facing strings in core; UI layers read `degree`, `halfCrit`, `trueCritical` for localization/effects.
