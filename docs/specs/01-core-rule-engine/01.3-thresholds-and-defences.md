## 1) Intent

Define how to compute **Defence Threshold (DT)** and derive **Challenge Threshold (CT)** for any test. Provide deterministic formulas and pure-function APIs consumed by 01.1 (resolution) and 03.5 (talent tests). Keep defence **passive by default** unless a rule explicitly grants an active defence.

Out of scope: damage/condition effects (consumers apply based on 01.1 outcomes).

---

## 2) Concepts

* **DT (Defence Threshold):** Baseline difficulty to affect a target with an attack; derived from target gear/effects.
* **CT (Challenge Threshold):** The number a test must meet/beat; equals DT for most attacks, or a fixed/table value for other tests.
* **Situational modifiers:** Additive adjustments from cover, visibility, range, and conditions; applied after DT when forming CT.
* **Relevance:** Only **relevant** gear/effects contribute to DT for a given action.

---

## 3) Deterministic formulas (normative)

**R-01.3-01 (DT base).**
`DT = 11 + Σ(relevantGearModifiers) + Σ(relevantEffectModifiers)`

**R-01.3-02 (CT for attacks).**
For `test.kind==='attack'` with `vs:'dt'`:
`CT = DT(target, ctx) + Σ(situationalModifiers(attacker, target, ctx))`

**R-01.3-03 (CT for attribute/fixed/table tests).**

* If `vs:'fixed'`: `CT = fixedCT + Σ(situationalModifiers)`
* If `vs:'table'`: `CT = lookupRuleTable(tableId, attacker, target, ctx) + Σ(situationalModifiers)` (missing rows ⇒ validation error)
* If `test.kind==='none'`: `CT` is not required (auto‑apply effect)

**R-01.3-04 (Relevance selection).**
A gear/effect modifier is **relevant** when either:

1. It declares `appliesTo` including one of the talent test **tags** (e.g., `'melee'`, `'ranged'`, `'spiritual'`, `'grapple'`), **or**
2. It declares `appliesTo:['all']`.

If a modifier does not declare `appliesTo`, apply a default mapping by **kind**:
`heavy → melee`, `nimble → melee|ranged`, `adept → ranged`, `spiritual → spiritual`. (Engine may refine via data patches; see 03.1.)

**R-01.3-05 (Passivity).** DT is **passive** by default; an **active defence** exists only if a talent/item grants it, with timing/cost defined by that rule (02.2 governs any cost symbol semantics).

## 4) Pure-function API

```ts
/** @spec 01.3 */
export interface Context {
  cover?: number;          // additive; e.g., +2 for light cover
  visibility?: number;     // additive penalties/bonuses
  range?: number;          // additive penalties from range increments (caller computes)
  targetBonuses?: number;  // other additive situational adjustments on behalf of the target
  attackerBonuses?: number;// other additive situational adjustments on behalf of the attacker
}

/** @spec 01.3 */
export function computeDefenceThreshold(target: AvantActorData, testTags: string[] = [], ctx?: Context): number;

/** @spec 01.3 */
export function computeChallengeThreshold(
  test: Pick<TestSpec,'kind'|'vs'|'fixedCT'|'tableId'|'tags'>,
  attacker: AvantActorData,
  target: AvantActorData,
  ctx?: Context
): number;
```

## 5) Algorithm (pseudocode)

```text
function computeDefenceThreshold(target, testTags, ctx):
  mods = selectRelevant(target.gearMods, testTags)  // see R-01.3-04
  effects = selectRelevant(target.conditions, testTags)
  dt = 11 + sum(mods) + sum(effects)
  return dt

function computeChallengeThreshold(test, attacker, target, ctx):
  if test.kind === 'attack' && test.vs === 'dt':
    base = computeDefenceThreshold(target, test.tags, ctx)
  else if test.vs === 'fixed':
    assertNumber(test.fixedCT) // else E_SCHEMA_VALIDATION
    base = test.fixedCT
  else if test.vs === 'table':
    base = lookupRuleTable(test.tableId, attacker, target, ctx) // may throw E_SCHEMA_VALIDATION
  else:
    throw AvantError(ErrorCode.SCHEMA_VALIDATION, { path: 'test.vs' })
  situational = (ctx?.cover ?? 0) + (ctx?.visibility ?? 0) + (ctx?.range ?? 0) + (ctx?.targetBonuses ?? 0) + (ctx?.attackerBonuses ?? 0)
  return base + situational
```

## 6) Validation & errors

**V-01.3-01** Unknown gear modifier kinds or malformed entries **MUST** throw `E_SCHEMA_VALIDATION` with the offending path/id.
**V-01.3-02** `vs:'table'` with a missing or invalid `tableId` or lookup result **MUST** throw `E_SCHEMA_VALIDATION`.
**V-01.3-03** Non‑finite intermediate CT/DT values **MUST** throw `E_CORE_CT_INVALID`.

---

## 7) Acceptance Criteria (AC)

**AC-01.3-01** With no gear/effects and empty context, `computeDefenceThreshold(target)` returns **11**.

**AC-01.3-02** Adding a relevant `gearMod:+2` increases DT to **13**; removing it restores **11**.

**AC-01.3-03** For an attack test with zero situational modifiers, `CT === DT`.

**AC-01.3-04** With `ctx.cover=+2`, `CT = DT + 2`.

**AC-01.3-05** A fixed‑CT attribute test uses `fixedCT` and ignores the target’s DT, still applying situational modifiers.

**AC-01.3-06** A table‑driven test retrieves a numeric CT from the table; missing entry throws `E_SCHEMA_VALIDATION`.
