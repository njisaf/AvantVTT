## 1) Intent

Define the normalized, engine‑facing **Talent** data contract used for authoring, validation, execution, and UI rendering. A Talent represents an actionable rules entry (attack, maneuver, utility, reaction, ongoing)
with cost, requirements, targeting, and effects.

Out of scope: layout/styling of sheets/cards; setting prose.

---

## 2) Concepts & symbols

* **Cost symbols (02.2):** ◯ (AP), ⊖ (Simultaneous), ⊚ (Variable), ⊘ (Immediate no‑cost), ⊜ (Simultaneous no‑cost).
* **Test (01.1/01.3):** An optional **test** block specifies how to derive **CT** and which attribute/attack applies.
* **Targets & areas:** Single, multi, and geometric shapes (cone/emanation/line/burst) with numeric distances (feet).
* **Effects:** A structured list of atomic effects applied by the engine/UI (damage, conditions, movement, resource changes, flags).
* **Augmentation:** Optional list of PP‑priced upgrades; constrained by the actor’s **PP Limit** per power.

## 3) TypeScript model (normative)

```ts
/** @spec 03.5 */
export type ActionCostSymbol = '◯' | '⊖' | '⊚' | '⊘' | '⊜';

/** @spec 03.5 */
export type AreaKind = 'burst' | 'cone' | 'line' | 'emanation';

/** @spec 03.5 */
export interface Targeting {
  kind: 'self' | 'single' | 'multi' | 'area';
  maxTargets?: number;           // for 'multi'
  area?: { kind: AreaKind; size: number }; // feet
  reachOverride?: number;        // optional override for melee reach (feet)
  requiresLOS?: boolean;         // line of sight
}

/** @spec 03.5 */
export type TestKind = 'attack' | 'attribute' | 'none';

/** @spec 03.5 */
export interface TestSpec {
  kind: TestKind;                 // 'none' for auto‑apply talents
  attribute?: 'focus'|'grace'|'intellect'|'might'; // for attribute tests
  vs?: 'dt' | 'fixed' | 'table';  // compute CT per 01.3
  fixedCT?: number;               // if vs === 'fixed'
  tableId?: string;               // if vs === 'table' (lookup in rules table)
  tags?: string[];                // e.g., ['melee','ranged','grapple'] affects DT relevance
}

/** @spec 03.5 */
export interface DamageSpec {
  dice: string;                   // e.g., '2d6+3'; parsed by engine damage roller
  type?: string;                  // e.g., 'physical','fire'
  persistent?: boolean;           // ongoing damage flag (tick rules elsewhere)
  onCrit?: 'double'|'extra'|'none'; // how crits modify this damage block
}

/** @spec 03.5 */
export interface ConditionSpec {
  id: string;                     // canonical condition id
  intensity?: number;             // stack/intensity
  duration?: string;              // e.g., 'endOfTurn', '1 minute'
}

/** @spec 03.5 */
export interface MovementSpec {
  type: 'push'|'pull'|'slide'|'teleport';
  distance: number;               // feet
}

/** @spec 03.5 */
export interface ResourceSpec {
  resource: 'fortune'|'power'|'ap'|'hp'|string; // extensible
  delta: number;                  // positive/negative change
  clamp?: boolean;                // clamp to valid range
}

/** @spec 03.5 */
export type Effect =
  | { type: 'damage'; data: DamageSpec }
  | { type: 'condition'; data: ConditionSpec }
  | { type: 'movement'; data: MovementSpec }
  | { type: 'resource'; data: ResourceSpec }
  | { type: 'flag'; data: Record<string, unknown> };

/** @spec 03.5 */
export interface Augmentation {
  id: string;
  name: string;
  ppCost: number;                 // spends actor Power Points
  changes: Partial<TalentData>;   // shallow overlay: can add/modify cost, test, effects, targeting
  tags?: string[];
}

/** @spec 03.5 */
export interface TalentData {
  id: string;
  name: string;
  level?: number;                 // if gated by level
  traits?: string[];
  requirements?: string;          // freeform requirement text/ids; validation may parse
  trigger?: string;               // text/id for reactions/immediates
  duration?: string;              // for simultaneous actions
  frequency?: string;             // e.g., 'once per turn', 'once per encounter'
  cost: ActionCostSymbol[];       // sequence like ['◯','◯']
  test?: TestSpec;                // omitted if automatic
  targeting?: Targeting;          // omitted if self/ambient
  effects: Effect[];              // at least one atomic effect
  augmentations?: Augmentation[]; // optional upgrades priced in PP
}
```

## 4) Validation & invariants

**R-03.5-01** `cost` **MUST** be a non‑empty array of recognized symbols; immediate/no‑cost actions use `['⊘']` or `['⊜']`.

**R-03.5-02** If `test.kind==='attack'` the CT **MUST** be derived **vs:'dt'** unless a specific talent rule states otherwise.

**R-03.5-03** If `test.kind==='attribute'`, `attribute` **MUST** be set and CT provided by `vs` (fixed/table) or by a rules reference.

**R-03.5-04** When `targeting.kind==='area'`, an `area` object with numeric `size` (feet) **MUST** be provided.

**R-03.5-05** `effects` **MUST** contain at least one entry; unknown `Effect.type` values **MUST** be rejected with `E_SCHEMA_VALIDATION`.

**R-03.5-06** `augmentations[*].ppCost` **MUST** be ≥1 and each augmentation’s **changes** **MUST NOT** produce an invalid Talent.

**R-03.5-07** Applying augmentations during play **MUST** respect the actor’s `perPowerLimit` (03.1) for total PP spent on this talent instance.

**R-03.5-08** Damage dice strings **MUST** parse using the engine’s dice parser; invalid expressions throw `E_DICE_EXPR`.

## 6) Acceptance Criteria (AC)

**AC-03.5-01** Minimal attack talent validates: `cost:['◯']`, `test:{ kind:'attack', vs:'dt' }`, `targeting:{ kind:'single' }`, one `damage` effect; `buildTestInput` yields a valid 01.1 input.

**AC-03.5-02** Area talent validates only if `area.size` (feet) is provided; missing size produces `E_SCHEMA_VALIDATION` at `targeting.area.size`.

**AC-03.5-03** Attribute test talent requires an `attribute` and a CT derivation (fixed/table); otherwise `E_SCHEMA_VALIDATION`.

**AC-03.5-04** Invalid damage dice (e.g., `2dX`) throws `E_DICE_EXPR`.

**AC-03.5-05** Applying an augmentation with `ppCost` greater than actor’s remaining PP throws `E_SCHEMA_VALIDATION` with `{ path:'augmentations[*].ppCost' }`.

**AC-03.5-06** Applying multiple augmentations that would exceed `perPowerLimit` is rejected with `E_SCHEMA_VALIDATION`.

**AC-03.5-07** Serialization: a normalized `TalentData` round‑trips to JSON without loss.

## 7) Examples

* **Basic Strike (melee):** `cost:['◯']`, `test:{ kind:'attack', vs:'dt', tags:['melee'] }`, `targeting:{ kind:'single' }`, `effects:[{ type:'damage', data:{ dice:'1d8+grace', type:'physical', onCrit:'double' } }]`.

* **Shove:** `cost:['◯']`, `test:{ kind:'attack', vs:'dt', tags:['grapple'] }`, `effects:[{ type:'movement', data:{ type:'push', distance:5 } }]`.

* **Fire Burst:** `cost:['◯','◯']`, `test:{ kind:'attribute', attribute:'intellect', vs:'fixed', fixedCT:15 }`, `targeting:{ kind:'area', area:{ kind:'burst', size:15 } }`, `effects:[{ type:'damage', data:{ dice:'2d6+intellect', type:'fire', onCrit:'extra' }}]`.

* **Augment: Intensify:** `ppCost:2`, `changes:{ effects:[{ type:'damage', data:{ dice:'+1d6' }}] }` (engine interprets prefix `+` as add‑dice to the first damage block).
