## 1) Intent

Define the **Action Points (AP)** budget and the semantics for **action cost symbols** used by talents and UI. Provide pure functions to parse cost, check affordability, and debit/track costs—including immediate and simultaneous actions.

Out of scope: initiative/phases beyond per‑turn AP refresh; UI styling.

---

## 2) Symbols & meanings

* **◯ (AP):** One Action Point of cost. A sequence (e.g., `['◯','◯','◯']`) indicates total AP cost.
* **⊖ (Simultaneous):** The action’s effect spans time; any listed AP symbols still cost AP when declared.
* **⊚ (Variable):** Cost is chosen at use time within bounds defined by the talent (e.g., 1–3 AP) and affects potency.
* **⊘ (Immediate, no cost):** May be taken off‑turn; no AP cost.
* **⊜ (Simultaneous, no cost):** Spans time but does not cost AP.

> Notes: The **symbol** sequence is authoritative for cost semantics; the **Talent** text may impose additional frequency/limits.

---

## 3) Defaults & timing

* **AP per turn:** Default **3 AP** available at the start of a creature’s turn.
* **AP cannot be negative.** Attempts to overspend are rejected.
* **Refresh:** AP resets at the start of each of the creature’s turns (encounter time).
* **Immediate (⊘):** Allowed outside the creature’s turn and does not affect AP.
* **Simultaneous (⊖/⊜):** Duration is tracked; effects persist per Talent’s `duration`.

## 4) TypeScript API (normative)

```ts
/** @spec 02.2 */
export type ActionCostSymbol = '◯' | '⊖' | '⊚' | '⊘' | '⊜';

/** @spec 02.2 */
export type ParsedCostKind = 'ap' | 'immediate-free' | 'simultaneous' | 'simultaneous-free' | 'variable';

/** @spec 02.2 */
export interface ParsedCost {
  kind: ParsedCostKind;
  ap: number;                  // total AP required now (for 'ap' and 'simultaneous')
  variable?: { min: number; max: number }; // when kind==='variable'
}

/** @spec 02.2 */
export interface TurnState { ap: number; /* other timing flags as needed */ }

/** @spec 02.2 */
export function parseActionCost(symbols: ActionCostSymbol[], bounds?: { min?: number; max?: number }): ParsedCost;

/** @spec 02.2 */
export function canPayCost(state: TurnState, cost: ParsedCost): boolean;

/** @spec 02.2 */
export function debitCost(state: TurnState, cost: ParsedCost): TurnState; // pure: returns new state

/** @spec 02.2 */
export function beginTurn(baseAP: number = 3): TurnState; // resets to base
```

## 5) Rules & invariants

**R-02.2-01** `parseActionCost(['◯','◯'])` yields `{ kind:'ap', ap:2 }`.

**R-02.2-02** If the sequence contains **⊖** plus AP symbols (e.g., `['⊖','◯']`), the parsed kind is `simultaneous` and `ap` equals the count of AP symbols.

**R-02.2-03** A sequence containing only **⊘** yields `{ kind:'immediate-free', ap:0 }`.

**R-02.2-04** A sequence containing only **⊜** yields `{ kind:'simultaneous-free', ap:0 }`.

**R-02.2-05** A sequence containing **⊚** must provide bounds; parsed kind is `variable` with `{ min,max }`. The caller chooses a specific AP within bounds at use time.

**R-02.2-06** `canPayCost` returns **false** if `state.ap < cost.ap` for kinds that consume AP.

**R-02.2-07** `debitCost` **MUST NOT** produce negative AP; insufficient AP throws `AvantError(ErrorCode.ENGINE_RULE_VIOLATION, { rule:'overspend-ap' })`.

**R-02.2-08** `beginTurn()` resets AP to **3**, unless a rules effect overrides the base.

## 6) Acceptance Criteria (AC)

**AC-02.2-01** Parsing: `['◯','◯','◯'] → {kind:'ap', ap:3}`; `['⊖','◯'] → {kind:'simultaneous', ap:1}`; `['⊘'] → {kind:'immediate-free', ap:0}`; `['⊜'] → {kind:'simultaneous-free', ap:0}`; `['⊚']` with `{min:1,max:3}` → `{kind:'variable', ap:0, variable:{min:1,max:3}}`.

**AC-02.2-02** Affordability: With `state.ap=2`, `canPayCost(ap:3)` is **false**; `canPayCost(ap:2)` is **true**.

**AC-02.2-03** Debit: With `state.ap=3`, debiting `ap:2` returns a new state with `ap=1`.

**AC-02.2-04** Overspend: Debiting `ap:4` from `ap:3` throws `ENGINE_RULE_VIOLATION` (rule: `overspend-ap`).

**AC-02.2-05** Turn start: `beginTurn()` returns `{ ap:3 }` by default; `beginTurn(4)` returns `{ ap:4 }`.
